# 云端模型接入设计（厂商 API · 首版火山/豆包）

状态：设计已确认，待实施。首版实现火山方舟 / 豆包，其余厂商留可插拔插槽。

## 0. 为什么会有这份设计

现状是**刻意的本地约束**：`app/core/semantic.py` 头部写着「语义判断只允许本地模型……
没有任何云端调用路径」，`tools/fetch_llm.py` 同样记录「素材不出机器」排除了云端接口。
本设计把这条约束从"写死在代码里"改成**用户可控开关（默认关闭）**，并如实标注外发代价。

本机装不上 llama-cpp-python（无 cp313 轮子、无编译器），只能退到 Ollama 本地 HTTP，
因此界面上语义判断长期显示"降级运行"。云端接入同时解决这个老问题。

## 1. 目标与非目标

目标：

- 语音转写与语义判断两处能力都能切到厂商 API，且**默认仍为本地**；
- 沿用已有的正确性保障：词级时间戳重建句子、静默吸附分块、跨块去重、缓存、预算、降级；
- 云端不可用时自动回退本地，并如实说明原因与"本次外发了什么"；
- 换第二家厂商 = 新增适配器 + 一份档案，不改调用方。

非目标（第一版明确不做）：

- 不做多厂商自动择优 / 自动比价；
- 不做费用估算（价格会变），只报**音频时长与请求次数**；
- 不做流式转写（讯飞式 WebSocket 分帧）：每次请求上传**一整段完整音频文件**并一次返回，
  长片靠"切成多段、逐段请求"覆盖（见 §3），不做分帧推送；
- 不做"半云端半本地"的拼接：块级失败一律整体回退本地重跑（理由见 §7）；
- 不改动本地链路的行为与默认值。

## 2. 分层与边界

```
调用方（AnalysisWorker）
  ├── AsrEngine / CloudAsrEngine        同形：transcribe / transcribe_cached
  │        └── AsrTransport（适配器协议）  ← 火山：VolcFlashAsrTransport
  └── SemanticJudge（含 CloudLlmJudge）   judge / available / describe
           └── JudgeTransport（适配器协议） ← 火山：VolcArkChatTransport
核心（不动）：plan_chunks / _extract_audio / _assign_to_owner_chunk /
             build_sentences / parse_verdict / Budget / CacheStore
```

新增 `app/core/providers.py`——**唯一一处知道"厂商"是什么的地方**：

| 符号 | 职责 |
| --- | --- |
| `ProviderProfile` | 一份厂商档案（字段见 §5） |
| `ProfileRegistry` | 从 `AppConfig.providers` 读出档案，含内置火山默认档案 |
| `resolve_api_key(profile)` | Key 解析：环境变量 `DRAMA_<ID>_API_KEY` 优先，其次档案里的 `api_key` |
| `describe_egress(profile, capabilities)` | 给界面与日志用的一句话："将把音频/文本发往 `<host>`" |
| `AsrTransport` / `JudgeTransport`（Protocol） | 厂商适配器协议，见 §4 |

两条外发路径的协议边界必须收敛在这两个 Protocol 上：厂商差异（鉴权、信封、时间戳单位）
只允许出现在适配器里，不得渗进 `CloudAsrEngine` / `CloudLlmJudge`。

## 3. 云端转写 `CloudAsrEngine`

方法签名与本地 `AsrEngine` 完全同形，内部复用现成件：

1. **分块**：`plan_chunks(total_seconds, chunk_seconds=600, overlap_seconds=15, snap_point=…)`
   —— 静音吸附沿用本地逻辑；600 秒/块在 16k 单声道下约 19MB（wav），
   远低于极速版 100MB / 2h 上限，且贴近官方"二进制流尽量 20M 以内"的建议。
2. **抽音**：`_extract_audio(ffmpeg, media, out, start, duration)`（16k 单声道）；
   优先压成 mp3/aac 以省流量——用 `check_encoders(binaries, names=("libmp3lame", "aac"))`
   探测（现有的 `check_encoders` 只查 libx264/aac，是导入兼容性用的，这里按需显式传名字），
   都不可用时回退 wav（不新增硬依赖）。
3. **上传**：逐块 `POST` 极速版接口，`audio.data` 走 base64（**不使用 `audio.url`**：
   源片不上传到任何公网存储）；块间串行，避免并发把出口带宽打满。
4. **映射**：`utterances[].words[]`（毫秒）→ `AsrWord`（`Fraction` 秒、`chunk_index`、
   `probability` 取 word 级 confidence）；`utterances[]` → `AsrSegment`；
   **加回块起点偏移**（方案 §7.3）后交给 `_assign_to_owner_chunk` 去重、`build_sentences` 重建句子。
5. **缓存**：`CacheKey.build("asr", fingerprint, audio_stream=…, backend="volc-flash",
   model=…, resource_id=…, chunk=…, overlap=…)` —— 换后端**绝不能**复用旧转写；
   旧键（本地）保持原样，历史缓存继续命中。
6. **失败语义**：网络/鉴权/额度异常统一抛 `ModelUnavailableError`（消息里带厂商返回的
   `X-Api-Message` 与 logid），由 `AnalysisWorker` 决定回退本地。

接口要点（火山极速版，已核对官方文档）：

- `POST https://openspeech.bytedance.com/api/v3/auc/bigmodel/recognize/flash`
- 头：`X-Api-Key`、`X-Api-Resource-Id: volc.bigasr.auc_turbo`、`X-Api-Request-Id`(UUID)、`X-Api-Sequence: -1`
- 体：`{"user": {"uid": …}, "audio": {"data": "<base64>", "format": "wav|mp3", "rate": 16000, "channel": 1},
  "request": {"model_name": "bigmodel", "show_utterances": true, "enable_punc": true, "enable_itn": true}}`
  —— `show_utterances=true` 是拿到 `words[]` 的**必需开关**，缺它就只剩整段文本。
- 返回：响应头 `X-Api-Status-Code: 20000000` 为成功；体里 `audio_info.duration` 是毫秒时长，
  `result.utterances[].words[]` 每词带 `start_time/end_time`（毫秒）。
- 已知硬限：单文件 ≤2 小时 / ≤100MB；格式 wav / mp3 / ogg opus。
  600 秒/块的分块让两者都天然满足（见 §7 的"源片超长"一行），不做静默截断。

成本口径：按**输入音频时长**计费；日志与检查器只报"上传了 N 分钟 / M 块"，不报金额。

## 4. 云端语义判断 `CloudLlmJudge`

与 `OllamaJudge` 并列的 `SemanticJudge` 实现，走**厂商适配器 + 统一请求体**：

- 协议：`JudgeTransport.complete(prompt) -> str`；火山适配器 = OpenAI 兼容
  `POST {base_url}/chat/completions`（`Authorization: Bearer <key>`，`model=<档案里的 judge_model>`，
  `temperature=0.1`、`max_tokens=160`）。
- 提示词、严格解析（`parse_verdict`）、预算（`Budget`，沿用 24 次）、
  `VERDICT_UNPARSEABLE` 如实标记——全部复用，不新造一套。
- `available()`：打一次**最小 chat 请求**（`max_tokens=1`）作为连通性探测，失败即视为不可用。
  不依赖 `GET /models`——不同厂商是否提供该端点不一致，探测手段必须只依赖协议主干。
- **显式绕过系统代理**：本机 `http_proxy` 会把请求交给代理（Ollama 路径已有先例，
  回环地址曾被代理断开）。档案里提供"使用系统代理"开关，默认关闭。
- 判断只发**候选点前后的台词文本片段**（`JudgmentRequest.to_prompt_dict()`），不发画面。

后端偏好的表达与 §5 的配置一一对应，不另立枚举：

| 偏好 | 配置形态 | 行为 |
| --- | --- | --- |
| 仅本地（默认） | `backend_prefs.judge = "local"` | 与今天完全一致（llama.cpp → Ollama → 降级） |
| 云端优先 | `backend_prefs.judge = "<profile_id>"` + `fallback_to_local = true` | 云端不可用即回退本地，日志写明原因 |
| 仅云端 | 同上 + `fallback_to_local = false` | 不回退；失败即降级为规则评分并如实标注 |

## 5. 配置与界面

`AppConfig` 新增两个字段（沿用 JSON，失败一律降级默认值）：

```json
{
  "providers": [
    {
      "id": "volc",
      "label": "火山方舟 / 豆包",
      "base_url": "https://ark.cn-beijing.volces.com/api/v3",
      "asr_endpoint": "https://openspeech.bytedance.com/api/v3/auc/bigmodel/recognize/flash",
      "asr_resource_id": "volc.bigasr.auc_turbo",
      "asr_model_name": "bigmodel",
      "judge_model": "",
      "api_key": "",
      "enabled": false,
      "allow_upload": false,
      "use_system_proxy": false
    }
  ],
  "backend_prefs": { "asr": "local", "judge": "local" },
  "fallback_to_local": true
}
```

两个开关的语义必须分清，否则会出现"以为没外发其实发了"：

- `enabled`：档案已通过连通性测试、**允许被 `backend_prefs` 选中**；
- `allow_upload`：**外发许可**（转写要上传音轨、语义判断要上传台词文本，两者都受它约束）。

任一为 false 即零外发：`backend_prefs` 指向该档案但开关没开时，直接按本地路径执行并在日志说明，
不静默降级、也不偷偷调用。`backend_prefs` 的取值是 `"local"` 或某个档案 `id`。

方案快照（`.drama-project`）**不含**档案与 Key：快照只记"能不能复现这次分集"，不含凭据。

界面：`app/gui/panes/model_form.py` 新增一张 Card「云端模型（厂商 API）」：

- 档案下拉（首版只有火山）+ 启用开关；
- 字段：`base_url` / `judge_model` / API Key（输入框标注"明文保存在本地配置文件，
  可用环境变量 `DRAMA_VOLC_API_KEY` 覆盖"）；
- **「允许外发素材」复选框**：勾选后才允许保存启用，旁边常驻一行 `describe_egress()`
  的结果（明示"转写=上传整条音轨；语义判断=上传候选点前后台词文本，不含画面"）；
- 「测试连通性」按钮：分别打一次最小转写与最小判定请求，显示结果与耗时；
  失败时不允许启用（避免"以为通了、分析时才回退本地"）。

## 6. 隐私与告知

- 默认**不外发**：档案默认 `enabled=false`、`allow_upload=false`，不给任何隐式外发路径。
- 开启时明示代价（见上），并在分析开始时要求一次确认（复用 `message.confirm` 通道，
  自动化里可 patch），确认结果记入日志。
- 每次分析在右栏检查器追加一条 `LEVEL_INFO` 记录：
  `外发：音频 600 秒 / 6 块 → openspeech.bytedance.com；文本 12 次 → ark.cn-beijing.volces.com`。
- 文档同步（**必须改，否则文档撒谎**）：`app/core/semantic.py` 头部「没有任何云端调用路径」、
  `tools/fetch_llm.py` 的对应表述、`README.md` 的「已知限制 / 模型下载」两处，
  改写为"默认本地；云端为显式开启的可选后端，外发范围如 §6 所述"。
- Key 处理：不进日志、不进快照、不进错误弹窗（错误信息只回显厂商的 message / logid）。

## 7. 降级与错误处理

| 情况 | 行为 |
| --- | --- |
| 未启用档案 / 未勾选外发 | 零网络调用（单测断言请求计数为 0） |
| 缺 Key | 拒绝启用，界面指出配置位置 |
| 401 / 403 / 资源未开通 | 回退本地，日志写明"鉴权失败（含厂商 message）"与去控制台核对哪一项 |
| 429 / 5xx / 超时 / 网络不可达 | 回退本地，日志写明原因；连续失败**不重试轰炸**（每能力每轮最多重试 1 次） |
| 返回体缺 `words[]` | 不失败：记为限制"该后端未提供词级时间戳，候选点质量降级"，句子退化为分句级 |
| 源片超长（>2h） | 不阻断：分块（600 秒/块）天然覆盖单文件上限；日志报出**总时长与块数**，这是费用口径 |
| 块级失败（抽音失败 / 单块超限 / 某块请求失败） | **不做"半云端半本地"拼接**：立即升级为整体回退本地重跑，并说明是第几块失败。混合来源的时间码难以核实，宁可贵一点重跑 |
| 云端失败 | **不把分析判为失败**：阶段保留、结果来自本地，检查器如实标注来源 |

每条结果都要能回答"这次是谁算的"：`Transcript.model_tier` / `JudgmentVerdict.judge_id`
填后端标识（如 `cloud:volc-flash/bigmodel`、`cloud:volc/<judge_model>`）。

需要真 Key 的部分（手工关卡，不进 CI）：

- `tools/cloud_smoke.py`（新增）：用用户 Key 对 120 秒样片做一次真实转写 + 一次真实判定，
  打印句数、首末句时间码、耗时、外发字节数；与本地路径（本机已装哪个档位就用哪个）的结果

## 附：实施记录（与设计的差异 / 实现时才定下来的事）

1. **云端不接受 mp4。** 本地路径是把整片直接交给 Whisper 的，云端只收
   wav / mp3 / ogg，因此源片必须先抽音轨（16k 单声道）。`CloudAsrEngine` 用
   `resolve()` 判断"拿到的是源片还是已抽好的块"，避免重复抽音。
2. **优先压成 mp3 上传。** 600 秒 16k 单声道 wav 约 19MB（贴近官方"二进制流尽量
   20M 以内"），压到 64kbps mp3 约 5MB。探测编码器**不用**
   `ffmpeg.check_encoders()`——那个函数会把结果写回共享的
   `FfmpegBinaries.encoders`，而那份数据同时喂给导入兼容性检查（libx264 / aac），
   不能为查一个 mp3 编码器去动它。
3. **成败看响应头而不是 HTTP 码。** 极速版用 `X-Api-Status-Code` 判成败，
   HTTP 200 也可能是 45000151（格式不正确）。另外 **20000003 = 静音音频**：
   它说明鉴权与资源权限都是通的，因此连通性测试用 1 秒静音样片（不读用户素材、
   不依赖 ffmpeg），并把 20000000 / 20000003 都视为"可用"。
4. **没有词级时间戳时的降级方式。** 用厂商的 `utterances[]` 合成**分句级**的
   `AsrWord`（时间戳仍是厂商给的，只是粒度更粗），并记一条
   `ASR_NO_WORD_TIMESTAMPS` 风险——这样句子重建、候选点、审核页都还能工作，
   而降级是明说的；不这么做会让下游误判成"没有语音内容"。
5. **逐能力测通。** 一张档案上有两条能力，两个勾选框各自探测、各自切换：
   转写测不通不影响已测通的语义判断（反之亦然）。`enabled` 的语义因此精确化为
   "该档案已通过至少一项能力的连通性测试"，而"某能力此刻是否走云端"由
   `backend_prefs[能力] == 档案 id` 且 `enabled` 共同决定。
6. **缓存按后端隔离。** 云端缓存键含 `backend`，本地键保持原样；换后端/换厂商
   不会复用旧转写（时间戳分布不同，混用会让审核页与方案算出来的切点对不上）。

## 10. 风险与已决定的取舍

- **内存**：base64 上传单块最大约 25MB 字符串；因此块长固定 600 秒、串行上传，
  不提供"整片一次上传"（哪怕源片在 100MB 内）。
- **网络环境**：本机对境外接口不友好（hf-mirror、代理拦截均有前科），
  默认关闭系统代理；火山作为首版接入对象正是为了国内直连可用。海外厂商若被本机
  代理拦截，需在该档案里显式打开"走系统代理"。
- **质量回归**：云端转写的分词与标点由厂商给，句子重建质量需用真实素材对照；
  P2 的真机冒烟是放行条件，不靠"看起来没问题"。
- **不做费用闸门**：只报时长；若日后要预算硬闸，复用 `Budget` 的形状加一个按秒计数的上限即可。

## 11. 多厂商与协议化（第二版，已实现）

### 11.1 为什么要改

首版把"支持哪家"写死在代码里：`DEFAULT_PROFILES` 只有 volc，`cloud.py` 按
`profile.id` 硬编码映射适配器，界面上只能编辑那一家的地址与模型名。用户既加不了
新厂商，也无从选择别家。

### 11.2 核心改动：厂商是数据，协议是信封

- `ProviderProfile` 增 `judge_protocol` / `asr_protocol`，取值是**封闭集合**：
  `disabled` / `openai` / `anthropic` / `gemini` / `volc_ark`
  （`PROTOCOLS_BY_CAP` 规定每条能力允许哪些；语义判断支持前四种，
  转写支持 `disabled` / `openai` / `volc_ark`）。
  注意"火山方舟"只是**信封的名字**：volc 这家厂商的语义判断走的也是 `openai`，
  只有转写是方舟自己的极速版协议。
- `supports()` / `missing_config_reason()` / `describe_egress()` 全部按协议判定；
  新增 `chat_completions_url()` / `audio_transcriptions_url()` / `asr_target_url()` /
  `asr_target_host()` 作为**路径与主机名的唯一来源**——"告知用户发往哪台主机"与
  "适配器真的发往哪台主机"必须来自同一份计算（OpenAI 兼容转写根本没有
  `asr_endpoint` 字段，最容易漂）。
- `cloud.py` 的 dispatch 键从"厂商 id"改成"协议"，于是
  **加一家厂商 = 在 `DEFAULT_PROFILES` 加一份数据**，`cloud.py` 一行都不用改；
  新增一种*协议*才需要写适配器并在协议表里登记一行。测试
  `tests/test_cloud_dispatch.py` 用"新造一个谁也没注册过的 id 也能造出 transport"
  与"`cloud.py` 里不出现任何厂商 id 字面量"把这条约定机器化。
- 通用 HTTP 抽到 `cloud_http.py`（代理策略 / 超时 / 错误映射 / multipart / 静音样片），
  厂商文件只放厂商差异；`cloud_openai.py` 承载 OpenAI 兼容的两条能力，
  `cloud_anthropic.py` 与 `cloud_gemini.py` 承载两种原生对话协议，
  `cloud_volc.py` 只剩火山转写。

### 11.3 预置目录（16 家，顺序：国内 → 海外 → 自建/聚合）

volc 必须留在第一位（`ProfileRegistry.default()`、合并排序与既有断言都依赖它），
且它的 `judge_model` 保持空串——方舟的语义判断要填**推理接入点 ID**（ep-xxx），
没有可预置的官方默认值。

转写协议标 `openai` 的家数，是"该厂商提供 OpenAI 兼容的 `/audio/transcriptions`"：
OpenAI（whisper-1，支持词级粒度）、Groq、硅基流动（SenseVoiceSmall，只给分句）、
Mistral、DeepInfra。是否返回**词级时间戳**各家不一，缺词级时走 §7 的分句级降级
（`ASR_NO_WORD_TIMESTAMPS`）；智谱与阶跃是否提供该端点**待真机核实**，
核实前一律留 `disabled`——"配了却拿不到时间戳"比"不列出来"更坏。

### 11.4 云端模型页签（`模型管理 → 云端模型`）

`app/gui/dialogs/model_dialog.py`（`QTabWidget`：本地模型 / 云端模型）+
`app/gui/panes/provider_form.py`：左栏列表（内置标"（内置）"）+ 右栏字段编辑，
支持新增 / 复制为自定义 / 删除 / 恢复默认。约定：

- **合并的由来**：Key、外发许可、能力开关、模型名原本分散在「模型管理」的云端
  卡片与独立的「厂商管理」对话框里——同一份档案两处都能改，用户实测就撞上了
  （"为什么模型管理里要填 Key，厂商管理那里不就重复了"）。合并后只剩这一个页签，
  `provider_dialog.py` 随之退场；`build_model_dialog(providers_tab=True)` 供工具与
  测试直接停在这一页。
- **版式：连接一页完成，进阶配置收起**。首屏只保留 API Key、外发许可与连接状态，
  右上角主动作「保存并测试连接」；接口地址、协议、火山 `asr_endpoint` / 资源 ID、
  `id`、代理、完整模型清单与模型参数全部收进「进阶设置」（默认收起，点「新增」时
  自动展开，切换厂商时回到默认折叠）。校验发现缺字段会**自动展开**并指名缺什么。
- **本页不选择用途与模型**。语义判断、语音转写分别用哪个模型，统一由 §11.5 的
  「模型设置」负责。早期版本曾在首屏放两个模型下拉，和模型设置形成两套真相；
  现已删除，避免同一选择要在两处维护。
- **首屏状态只说明连接是否可用**：已连通（整份档案的必要能力都测通）/ 待测试。
  是否使用这家厂商、两条能力各自走本地还是云端，仍由 `backend_prefs` 决定；
  厂商页的保存与测试不写 `backend_prefs`。
- **模型清单是一张表**（`widgets/model_table.py`）：一行一个模型名，行内点
  「设为语义判断 / 设为转写」即指派（当前指派的带 ● 标记、按钮禁用），手填的行带
  「手填」小字与「删除」。清单 = `GET {base_url}/models` 拉回来的（点「刷新模型
  列表」重取，走 `ModelListWorker`，同一 `(base_url, key)` 命中内存缓存）+
  档案里的 `custom_models`（手填的，**会记住**）+ 当前指派的两条模型名（老配置里
  可能存在既不在接口清单、也没进手填清单的名字，不显示出来用户就看不到"现在用的
  是哪个"）。`providers.merge_model_choices()` 是合并规则的唯一定义。
- **连通性测通**：测哪几条能力由档案自身的配置完整性决定（协议启用且地址、候选
  模型名齐全），不看 `backend_prefs`。**仅保存**只写字段与模型名；**保存并测试连接**
  对每条已配置能力逐项 probe，全部通过才写 `enabled=True`，任意一条失败则保持
  `enabled=False` 并逐项写明原因（沿用"测通才允许启用"的硬约束）。两处共用
  `_validated_draft()` 校验，不会出现"一个按钮放行、另一个拦下"。
- **内置厂商 id 不可改、不可删**（代码里有默认值），可改字段，也可「恢复默认」
  （从 `config.providers` 删掉该 id 的覆盖项，Key 一并清空）；
- **编辑内置 = 同 id 覆盖**：`merge_profiles` 以 id 为键合并、`backend_prefs` 存的
  也是 id，因此覆盖不会让"已选中的后端"失效；
- **删除 / 恢复默认必须连带处理引用**：把 `backend_prefs` 里指向它的能力改回
  `LOCAL_BACKEND` 并在提示行说明，否则用户只会看到"云端静默失效"；

### 11.5 自定义接入与多协议

左侧「自定义接入」面向自建网关、聚合站和尚未预置的服务：用户填写服务名称、
API 地址、API Key，选择协议后手动添加模型名即可。内部 id 按服务名称自动生成
并保证不重复，不作为用户需要理解的概念展示。

| 协议 | 请求路径 | 鉴权 | 能力 |
|---|---|---|---|
| OpenAI 兼容 | `{base_url}/chat/completions` | `Authorization: Bearer` | 语义判断 |
| Anthropic Messages | `{base_url}/messages` | `x-api-key` + `anthropic-version` | 语义判断 |
| Google Gemini | `{base_url}/models/{model}:generateContent` | `x-goog-api-key` | 语义判断 |
| 火山方舟 | 档案里的 `asr_endpoint` | `X-Api-Key` + `X-Api-Resource-Id` | 转写 |

三种对话协议共用同一个 `JudgeTransport.complete()` 接缝，上层提示词、预算、
严格解析与本地回退逻辑完全复用。Anthropic / Gemini 没有通用的 `/models`
清单端点，界面会明确提示手动添加模型名，而不是把“没有清单”伪装成“没有模型”。
- 「模型管理 → 本地模型」页签只管本地档位（whisper / GGUF 的下载删除与「使用中」），
  与厂商页签互不干扰；厂商页留一行**只读的协议与外发预览**，让"会怎么发、发往哪台
  主机"一眼可见。
- 校验是纯逻辑（`providers.validate_profile`，核心层唯一一份）：id 形式与唯一性、
  名称非空、URL 必须 http(s)、转写模型名、火山专用字段。**"选了语义判断协议却没填
  模型名"不算结构错误**——预置的方舟档案本身就是这种状态，由
  `missing_config_reason()` 如实说明"这项能力还缺什么"。

### 11.6 模型设置（两条能力各选一个模型，本地与云端混用）

`app/gui/dialogs/model_setup_dialog.py` + `app/gui/panes/model_setup_form.py`，
入口在「工具 → 模型设置…」。它回答的是"**语音转写 / 语义判断现在到底在用哪个模型**"——
原先这个问题散在三个窗口里（本地模型页签管档位、厂商页签管档案、旧的「选择云端模型」
对话框管云端模型名），用户要在三处之间来回跳，还常常跳错。

- **两张卡，一条能力一张**：每张先选走本地还是云端、再选具体模型。**两条能力各选
  各的**——转写本地 + 判断云端（或反过来）是常态，不是特例。
- **本地一侧只列已安装的**（`installed_whisper_tiers` / `installed_llm_specs`）；
  当前配置里那个档位即使没装也补进去并标「（未安装）」，免得用户以为自己配的模型
  丢了。下载仍在「模型管理 → 本地模型」，本页不放下载。
- **云端一侧列出全部厂商**：行尾标 `_short_block()` 的短标记（未测通 / 未允许外发 /
  无 Key / 配置不全）。早先的「选择云端模型」只列"已配 Key 且能连通"的，其余一律
  消失——"下拉是空的"于是看起来像界面坏了，真正的原因反而被藏起来。完整的
  `block_reason()` 挂在该项的 tooltip 上。
- **清单是筛选框 + 单选列表**（`app/gui/widgets/model_list.py`）：厂商的 `/models`
  动辄几百条，"每行两个宽按钮"的表格会把模型名挤成省略号、一屏只剩四五行。筛选框
  同时当"手输模型名"用（方舟的 `ep-xxx`、自建网关的别名都不在清单里）。
- **状态行分清"生效"与"待保存"**：写的是**配置里此刻生效的**什么，另起一句说明这张
  卡上未保存的选择什么时候才切过去。把两者混成一句"已生效：xxx"是最容易骗到人的写法。
- **写 `backend_prefs` 不等于立刻外发**：是否真的走云端由 `block_reason()` 把关
  （档案必须"测通过 + 勾了允许外发素材"），核心层每次分析前重判一次，不满足就回落
  本地并把原因写进日志与检查器。所以本页可以放心让用户选云端——没生效时状态行
  **指名说出差哪一项**，并给出「去配置 Key…」直达「模型管理 → 云端模型」。
- **本页不碰 Key 与下载**：厂商地址 / Key / 协议在「模型管理 → 云端模型」，模型下载
  在「模型管理 → 本地模型」，这里只选模型。

### 11.6 零迁移与两处修正

- **旧配置零迁移**：老 `config.json` 里的 volc 条目没有协议字段，`merge_profiles`
  给已知 id 传 `fallback`（内置默认），因此补成 `openai` / `volc_ark`，
  能力判定与改造前完全一致（`tests/test_providers.py::test_old_config_zero_migration`）。
- **修正一**：`from_json` 的基底从 `DEFAULT_PROFILES[0]` 改为"按 id 找内置，找不到
  用全空档案"。此前自定义厂商会继承火山的地址与资源 ID，凭空"支持火山转写"。
- **修正二**：`asr_model_name` 的默认值从厂商专有的 `"bigmodel"` 改为空串
  （`VolcFlashAsrTransport` 内部本就有 bigmodel 兜底），否则每份新档案都会继承它。
- **修正三（合并时新增）**：`custom_models`（手填模型清单）是新增字段，老配置没有
  它就取空元组；`from_json` 刻意区分"字段缺失"与"空清单"——用户把自定义模型全删了
  是空清单，不该被当成缺失而回落基底。

### 11.8 待办（真机关卡，不进 CI）

逐家核实标"待核实"的项（智谱 / 阶跃是否提供 OpenAI 兼容转写），并对至少一家
OpenAI 兼容厂商跑一次真实判定 + 一段 30~120 秒样片转写：记录 HTTP 结果与**是否
返回 `words[]`**；无词级的保留但把注释改成"只给分句"，完全不支持的预置改回停用。
