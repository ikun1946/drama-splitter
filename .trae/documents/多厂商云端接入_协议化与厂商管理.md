# 多厂商云端接入：协议化 + 厂商管理

## Context

现在的云端接入只能选**一家**厂商（火山方舟 / 豆包）：`DEFAULT_PROFILES` 里只有 volc，
`app/core/cloud.py` 按 `profile.id` 硬编码映射适配器，"支持哪家"写死在代码里；界面上
「云端模型（厂商 API）」卡片只能编辑那一家的 address / model / key，用户既加不了新厂商，
也无从选择别家。

用户要求：**厂商可由用户自定义，并且尽量把大多数厂商都支持起来**。已确认三条取舍：

1. **只做 OpenAI 兼容协议 + 预置十几家**（不新增阿里 Paraformer / 腾讯 / 讯飞这类专有协议适配器，文档写清怎么加）；
2. **独立「厂商管理」对话框**承担新增 / 编辑 / 复制内置 / 删除 / 恢复默认；「云端模型」卡片只留"选厂商 + Key + 开关 + 测通 + 管理入口"；
3. **只选协议，路径用约定**（`/chat/completions`、`/audio/transcriptions`），不开放自定义路径与字段映射。

目标：**加一家厂商 = 加一份预置数据；只有新增*协议*才写适配器。**

## 现状关键事实（已核对，含行号）

- `app/core/providers.py`：`ProviderProfile`（id/label/base_url/asr_endpoint/asr_resource_id/asr_model_name/judge_model/api_key/enabled/allow_upload/use_system_proxy）；`supports()` 凭 `judge_model` / `asr_endpoint+resource_id` 判能力；`block_reason()` 逐项说明"为什么没生效"；`describe_egress()` 是外发告知的唯一文案来源；`merge_profiles()` 以 id 为键把用户配置盖在内置默认上。
- `app/core/cloud_volc.py`：`_post_json()`(L83-123)、`_http_error()`(L126-163)、`_silent_wav_bytes()`(L60-80) **与厂商几乎无耦合**；`VolcArkChatTransport`(L166-246) 本来就是 **OpenAI `/chat/completions` 形态**（Bearer、model/messages/temperature/max_tokens、解析 `choices[].message.content`，只有 `describe()` 里的"火山方舟"是厂商痕迹）；`VolcFlashAsrTransport`(L249+) 是火山专有协议（base64、`show_utterances`、靠响应头 `X-Api-Status-Code` 判成败）。
- `app/core/cloud_asr.py`：`CloudAsrEngine` 只覆盖 `_transcribe_range()`；L267 已有 `ASR_NO_WORD_TIMESTAMPS` 降级（用厂商 segments 合成粗粒度词）——**OpenAI 兼容转写缺 `words[]` 时直接复用它，零新增降级代码**；`egress_line()` 目前写的是 `egress_host(profile.asr_endpoint)`，OpenAI 兼容厂商没有 `asr_endpoint`，必须改。
- `app/gui/panes/model_form.py`：云端卡片 L279-366（含 `cloud_base_url` / `cloud_model` 两个输入框）；`_probe_cloud()` L824-844 **抄了一份**能力校验文案（多协议后必然漂移）；配置落盘走 `self._config.save(self._config_path)`（`_config_path` 是测试注入点）。
- GUI 约定：`DialogShell`（`app/gui/dialogs/base.py`）承载所有对话框；`main_window.py` L194/L207 是 `build_*_dialog()` / `open_*_dialog()` 工厂，L167 是「工具」菜单入口；`panes/__init__.py` 明写"分区只通过**公开信号**向上汇报"；测试/冒烟/截图**只允许 `build_*_dialog() + show()`，禁止 `exec()`**；弹窗统一走 `app/gui/widgets/message.py`。
- 受影响的既有断言：`tests/test_providers.py` L80 `len(merged) == 2`（预置变多后必改）、L41-43 volc 的 supports 断言（改造后必须仍然成立）、L57-65 `from_json` 容错（payload 带 `id="volc"`）；`tests/test_gui_smoke.py::TestCloudModelCard` 有 5 处 `form.cloud_model.setText("ep-test")`（卡片删掉该输入框后要改数据源）。
- `tools/cloud_smoke.py` **不存在**（设计文档里只是"计划新增"）——真机验收改用 GUI 测通 + 一次真实分析。

## 改动清单

### 1. `app/core/providers.py`：协议字段与判据

```python
PROTO_DISABLED = "disabled"; PROTO_OPENAI = "openai"; PROTO_VOLC_ARK = "volc_ark"
PROTO_LABELS = {…: "停用" / "OpenAI 兼容" / "火山方舟"}
PROTOCOLS_BY_CAP = {CAP_JUDGE: (DISABLED, OPENAI),
                    CAP_ASR:   (DISABLED, OPENAI, VOLC_ARK)}
```
注释要点：**协议是"信封的名字"，不是厂商名**——volc 这家厂商 `judge_protocol=openai`、`asr_protocol=volc_ark`；因此 judge 不需要"火山方舟"这个协议值。

- `ProviderProfile` 增 `judge_protocol` / `asr_protocol`（默认 `disabled`），进 `to_json` / `from_json`；`from_json` 的协议字段做**枚举容错**：非法值回落 `base` 的对应值（**不回落 disabled**，否则配置写错会静默关能力）。
- `supports()` 改为按协议判：judge = 协议非停用且 `judge_model` 非空；asr = 协议非停用且 `asr_configured()`（openai → `base_url` 非空；volc_ark → `asr_endpoint` + `asr_resource_id` 非空）。`egress_allowed()` 不动（默认零外发的保证不放松）。
- 新增 URL helper（唯一来源，防"告知的 host"与"真发的 host"漂移）：
  `chat_completions_url(base_url)` / `audio_transcriptions_url(base_url)` / `judge_target_url(profile)` / `asr_target_url(profile)` / `asr_target_host(profile)`。
- `describe_egress()` 按协议取主机（ASR 用 `asr_target_host`，judge 用 `egress_host(base_url)`）。
- 抽出 `missing_config_reason(profile, capability)`（只判"缺配置"：协议未选 / 缺模型名 / 缺地址 / 缺资源 ID），`block_reason()` = 三个开关前缀 + 它；`model_form._probe_cloud()` 改调它（消掉重复文案）。
- 新增 `validate_profile(profile, *, existing_ids)`（纯逻辑，GUI 只显示结果）：id 匹配 `[a-z0-9][a-z0-9_-]{0,31}` 且不与已有 id 冲突；label 非空；需要 `base_url` 时必须是 http(s) 且有 hostname；`volc_ark` 要求 endpoint + resource_id + model_name。
- **基底修正（行为变更，要在文档/commit 里写明）**：`from_json` 现在 `base = fallback or DEFAULT_PROFILES[0]`，未知 id 会**继承 volc 的地址与资源 ID**（自定义厂商凭空"支持火山转写"）。改为按 id 找基底，找不到用一份全空的 `_BLANK_PROFILE`。旧配置零迁移靠 `merge_profiles` 给已知 id 传 `fallback` 仍成立。

### 2. `app/core/cloud_http.py`（新）：把通用 HTTP 工具搬出来

从 `cloud_volc.py` 迁移：`_post_json → post_json`、`_http_error → http_error`、`_silent_wav_bytes → silent_wav_bytes`、`VolcArkChatTransport._extract_text → extract_chat_text`，新增 `post_multipart(url, fields, file_field, headers, *, timeout, use_system_proxy)`（标准库手搓 boundary，显式 content-type；错误体复用 `http_error`，非 JSON 错误体走 `raw[:200]`）。

`cloud_volc.py` 改为 `from .cloud_http import …`，**删除自己的副本；类名、构造签名、请求体、错误文案逐字不变**——`tests/test_cloud_judge.py` / `tests/test_cloud_asr.py` 里针对文案与 logid 的断言应当**一行不改即通过**，这就是"抽取没改行为"的证据。

### 3. `app/core/cloud_openai.py`（新）：OpenAI 兼容两个传输

- `OpenAiChatTransport(base_url, api_key, model, *, label="", use_system_proxy=False, temperature=0.1, max_tokens=160)`
  - `complete()`：POST `chat_completions_url(base_url)`，Bearer 头，体同现在的 volc chat（**即原 `VolcArkChatTransport` 泛化**，加 `label` 只影响 `describe()`）；`probe()` = 一次 `max_tokens=1` 的最小 chat；缺 base_url / key / model 一律本地拦截（零请求）。
  - `describe()`：`f"{label or 'OpenAI 兼容'} {model} @ {host}"`（volc 档案的 label 是"火山方舟 / 豆包"，既有断言"火山方舟"仍成立）。
- `OpenAiAsrTransport(base_url, api_key, model, *, label="", use_system_proxy=False)`
  - `transcribe_file()`：POST `audio_transcriptions_url(base_url)`，multipart：`file` + `model` + `language`（`yue→zh`，空则省略）+ `response_format=verbose_json` + `timestamp_granularities[]=word`；本地格式白名单 `.wav/.mp3/.ogg/.opus/.m4a/.flac/.webm`，其余直接拒绝（零请求）。
  - 解析判据（**核心**）：`words[]` → `ProviderWord`（秒×1000 取整）；`segments[]`/`duration` → 对应的 `ProviderSegment`/`duration_ms`；**有 segments 无 words → 返回 `words=[]`，交给既有 `ASR_NO_WORD_TIMESTAMPS` 降级**；`text` 为空且无时间戳 → 视为静音返回空结果；**有文本但一个时间戳都没有 → 抛 `ProviderError` 并提示该服务可能不支持 verbose_json**（绝不静默当静音，否则有对白的片段会被判成没语音）；返回体不是 JSON 对象 → 同样报错。
  - `probe()`：POST 1 秒 `silent_wav_bytes()`；2xx/静音 → 通过；401/403 → 失败（"鉴权失败"，这是唯一可靠的 Key 判据）；404/405 → 失败并提示"base_url 通常以 /v1 结尾且不要已含 /audio/transcriptions"；其余 4xx 且厂商说明命中 `audio|short|duration|silence|empty|format` → 退化用 `GET {base_url}/models` 验鉴权，通过则写 `probe_note`（"只验证了鉴权与路径，未验证转写模型"）供界面如实展示。

### 4. `app/core/cloud.py`：按协议分派

```python
JUDGE_BUILDERS = {PROTO_OPENAI: lambda p: OpenAiChatTransport(p.base_url, p.resolved_api_key(), p.judge_model, label=p.label, use_system_proxy=p.use_system_proxy)}
ASR_BUILDERS   = {PROTO_OPENAI: …, PROTO_VOLC_ARK: lambda p: VolcFlashAsrTransport(…)}
```
`build_*_transport()` 改用协议查表，**签名与"None = 该能力不可用"语义不变**（`select_judge` / `select_asr_engine` / `_probe_cloud` 三处调用点结构不动，只把"暂不支持该厂商"文案补上协议名）。旧的 `JUDGE_TRANSPORTS` / `ASR_TRANSPORTS` 两个按 id 的 dict 删除；`cloud.py` 里从此**不出现任何厂商 id 字面量**。

## 风险与取舍

1. **API Key 仍明文存 `config.json`**，多厂商后风险面变大。缓解：环境变量优先**已存在**，本次把它变成可见（厂商对话框显示 `DRAMA_<ID>_API_KEY`）+ README 明写"生产凭据用环境变量"。不做系统钥匙串（跨平台依赖与打包成本）。
2. **预置模型名会过时**（`glm-4` → 更新版本、带日期的模型名）。缓解：可在厂商管理里改；404 文案补"模型名可能已过期"。不拉远端模型清单（引入联网与缓存策略）。
3. **OpenAI 兼容 ASR 各家对 verbose_json / 词级时间戳支持差异大**：可能只给 segments、忽略 `timestamp_granularities`、甚至返回非 JSON。已按"有时间戳无 words → 降级；有文本无时间戳 → 报错；非 JSON → 报错"处理；`probe` 只承诺"鉴权与路径可用"，**词级是否可用靠 P5 真机核实**。
4. **误配置表现**：base_url 少写 `/v1` 或多写路径 → `probe` 阶段 404 暴露并给提示；内网地址 → `URLError` 已成 `ProviderError("网络不可达")`；允许 `http://`（本地 Ollama/LM Studio 必需），故不禁止明文 HTTP 到公网，靠外发预览与提示告知。
5. **`from_json` 基底修正是行为变更**（自定义 id 不再继承 volc 地址/资源），属修正，由测试固化并在文档与 commit 里写明。
6. **"没测通不许启用"不放松**：多厂商后更容易"选了一家、Key 填了、模型名不对"，逐能力探测 + 失败不启用 + 日志原因是唯一防线。
