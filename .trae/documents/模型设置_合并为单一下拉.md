# 模型设置：合并成单个下拉 + 整页做减法

## Summary

把「模型设置」的两张能力卡各**从 6 个控件压到 1 个可搜索下拉**，选项按「**本地模型在最上面，然后是云端模型**」排序，
并把整页多余的分步交互、厂商切换与保存流程一并去掉。

```
模型设置                                        [刷新清单]  [去配置 Key…]
──────────────────────────────────────────────────────────────
语音转写
  模型   [ whisper small — 484 MB              ▾ ]   ◀ 只有一个控件
  当前生效：本地 whisper small。

语义判断
  模型   [ 本地 Qwen3.5-2B Q4_K_M               ▾ ]
  当前生效：本地 Qwen3.5-2B Q4_K_M。
```

下拉展开后：

```
────────── 本地 ──────────
  whisper small — 484 MB              ●
  whisper large-v3 — 3090 MB
────────── 云端 ──────────
  ▸ 火山方舟 / 方言（当前生效）
      doubao-seed-asr
      ep-20260101
  ▸ 硅基流动 SiliconFlow
      FunAudioLLM/SenseVoiceSmall
      Qwen/Qwen3-8B
  ────────────────────────────
  另有 14 家厂商未配置 Key
```

## Current State Analysis

**每张能力卡当前有 6 个控件**（`model_setup_form.py`）：

| # | 控件 | 作用 |
|---|---|---|
| 1-2 | `btn_local` / `btn_cloud` 两个可勾选按钮 | 本地/云端二选一 |
| 3 | `local_combo` 本地下拉 | 选本机档位 |
| 4 | `provider_combo` 厂商下拉 | 16 家档案全列 |
| 5 | `btn_refresh` 刷新按钮 | 拉 `/models` |
| 6 | `model_list`（筛选框 + 列表） | 从清单里挑一个 |

**选一个云端模型的真实路径是 5 步**：点「云端厂商」→ 选厂商 → 点「刷新列表」→ 在筛选框里输入 → 点中某一行。
用户要的是"选一个模型"，却要先回答"走本地还是云端"、"哪家厂商"两个**界面自己知道答案**的问题。

**其余已确认的事实**（改动时要照顾到）：

- `DEFAULT_PROFILES` 共 **16 家**厂商，默认全部 `enabled=False`、无 Key。
  每家的 `/models` 动辄上百条 → 「16 家 × 几百模型」铺平一个下拉是**不可用**的，
  这决定了分组与过滤规则（§3b）。
- `block_reason(profile, capability)`（`providers.py:741`）已能逐项说清「为什么这家现在还不能用」，
  `_short_block()`（`model_setup_form.py:642`）已给出适合下拉行尾的**短标记**（无 Key / 未测通 / 未允许外发）。
  → **分组头直接复用 `_short_block`**，不新造一套文案。
- `ModelList` 控件**不能删**：`model_table.py:58`（厂商管理页）在用。
  本方案只是让模型设置页不再使用它。
- **待保存 vs 已生效的双状态**是当前最贵的一段逻辑：`_refresh_status()`（L526-568）+
  `_on_save()`（L572-630）+ `_block_reason_now()` 约 100 行，全是为了回答
  "我改完还没点保存，现在跑的到底是哪个"。
- **测试面**：`tests/test_gui_smoke.py::TestModelSetupDialog`（L2329-2710）13 个用例，
  其中 **37 处**引用 `set_backend` / `provider_combo` / `model_list` / `cloud_host` /
  `local_combo` / `btn_save` / `btn_local` / `btn_cloud`；
  `tools/gui_smoke.py:360-380` 同样引用旧控件。
- `register_worker(self, "model_list", worker)`（L475）是**单键**注册，
  而 §3c 要同时给多家厂商拉清单 → 这一处必须改成按厂商分键。

## Proposed Changes

### 1. 单个可搜索下拉（`NoWheelComboBox` + `setEditable(True)`）

每张卡只留一个控件。**用可编辑下拉而不是普通下拉**，一次解决两个原本需要额外控件的问题：

- **筛选**：几百个模型靠下拉自带的输入过滤定位，不需要再摆一个筛选框。
- **手输**：方舟的 `ep-xxx`、自建网关的别名都不在任何 `/models` 里，
  现在靠 `ModelList` 的筛选框兼任手输框（`selected_model()` L293-304）。
  可编辑下拉原生支持"框里打字但不在清单里"，这段能力不用另造控件。

选项数据用一个小结构体挂在 `UserRole`：

```python
@dataclass(frozen=True)
class ModelChoice:
    kind: str            # "local" / "cloud" / "header" / "note"
    label: str           # 下拉里显示的文字
    value: str = ""      # 存配置的值：档位名 或 模型名
    provider_id: str = ""
```

`header` 与 `note` 两类**禁用不可选**（`model().item(i).setEnabled(False)`），
只作分组标题和提示行。

### 2. 分组与排序（用户指定的核心）

严格按「本地在最上、然后云端」：

- **本地组**：只列**已安装**的档位（沿用 `_fill_local()` 现有口径），
  按 `WHISPER_TIERS` 目录顺序；当前配置指向但没装的，补一行标「（未安装）」。
  → 不产生"选了但用不了"的项。
- **云端组**：**按厂商分子组**，厂商内按 `/models` 原序。
  组内厂商顺序：**当前生效的那家排最前**，其余按档案原序 —— 让"现在在用什么"一眼可见。
- 本地组内，当前生效项加 `●` 前缀。

### 3. 哪些厂商进下拉（决定这个下拉能不能用）

16 家全列会毁掉可读性。规则：

| 厂商状态 | 下拉里怎么呈现 |
|---|---|
| **有 API Key** | 单独一个子组，列出 `/models` 全部模型；组头标 `当前生效` 或 `_short_block()` 的短标记 |
| 无 Key | **不单独成组**，全部合并成一条 note：`另有 N 家厂商未配置 Key` |

默认配置下有 Key 的厂商为 **0 家**，所以首次打开时云端组只有那一条提示 ——
这正是真实状态，不做假列表糊弄。

选中的若是 note 行则不可落库；用户想配置走右下「去配置 Key…」。

### 4. 整页做减法

**删掉**：两个后端切换按钮、厂商下拉、每卡的刷新按钮、筛选框 + 模型列表、`ModelList` 的使用。

**保留**：能力分组（两条能力各选各的，混用是常态）、当前生效状态行、
底部「刷新清单」「去配置 Key…」、本地模型下载与 Key 配置仍去原页面（职责边界不变）。

每张卡从 6 个控件 → 2 个（下拉 + 状态行）。整页从「点按钮 → 选厂商 → 刷新 → 筛选 → 选中」5 步 → **1 次点选**。

### 5. 选择即生效：去掉「保存设置」按钮

下拉里"浏览"（展开看）不会改 `currentIndex`，只有真正选中才变 →
**选择即写盘即生效**，按钮可以整个去掉。

顺带删掉 §Current State 里那约 100 行"待保存 vs 已生效"逻辑。

必须**保留**的是另一类提示，它与保存状态无关，是配置本身有效性：
选了云端但 `block_reason` 非空时，状态行指名说差哪一项
（如「当前生效：本地。已选云端 火山方舟，但尚未生效——未勾选允许外发素材。」）。

重建下拉选项时必须 `blockSignals`，否则刷新列表会误触发一次写入。

### 6. 厂商清单改为开窗自动拉取

统一下拉必须在展开前就有内容，所以：打开对话框时，对**所有有 Key 的厂商**各发一个
`ModelListWorker`，谁先回来先进谁，回来一项刷新一次下拉（渐进呈现，不等最慢的）。

- 状态行在拉取期间显示「正在拉取 N 家厂商的模型清单…」，拉完显示实际条数。
- 某家失败：它那个子组留一条 `载入失败（原因）` 的 note，不影响其他厂商。
- **不主动去拉没 Key 的厂商**（必然 401，白等超时）——沿用现有 `_request_models` 的这条判断。

### 7. 并发 worker 注册改造

`register_worker(self, "model_list", worker)`（L475）是单键，多厂商并发会互相顶掉。
改为按厂商分键 `f"model_list::{provider_id}"`，`self._worker`（单个）改为
`self._workers: dict[str, worker]`，`shutdown()` 全部取消。
`main_window.py:451` 的 worker 名册同步登记这些键。

### 8. 测试与工具

- **重写** `TestModelSetupDialog` 13 个用例（37 处旧控件引用）：
  - 下拉排序：本地项全部在云端项之前；云端按厂商分子组；当前生效厂商排在最前；
  - 只有有 Key 的厂商成组，其余合并为一条 note；
  - 选本地项 → 只写 `asr_model_tier`/`llm_model_key` + `backend_prefs=local`；
  - 选云端项 → 只写该厂商档案的模型字段 + `backend_prefs=<厂商 id>`；
  - 手输清单外的名字（`ep-mine`）能被接受并落库；
  - 选了云端但 `block_reason` 非空 → 状态行指名原因，且**不**写 `backend_prefs`；
  - 重建下拉不触发写入（`blockSignals` 回归测试）。
- `tools/gui_smoke.py:360-380` 改为断言下拉结构；`run.py --ui-smoke` 同步。
- `tools/screenshot_gui.py:279` 的截图内容自然更新，重录模型设置页。
- README「模型设置」段落同步（控件从 6 个变 1 个的表述）。

## Assumptions & Decisions

- **不用厂商下拉，是因为 16 家里默认 0 家可用**：真正的选择空间是"本机装了的几个模型
  + 配好 Key 的那几家"。厂商选择被压缩成"选模型"这一个动作，符合用户说的简单易操作。
- **厂商按子组呈现而不是前缀拼接**（如「硅基流动 · Qwen/Qwen3-8B」）：
  同一模型名可能出现在多家厂商下，拼接后下拉里会出现重复名字，用户分不清是哪家。
  子组头给出厂商名，归属明确。
- **本地组只列已安装项**：避免"选了但用不了"。未安装的当前项仍列出并标注，
  因为用户需要知道"配置指向的模型其实没了"。
- **无 Key 的厂商合并成一条提示而不是隐藏**：直接隐藏会让人以为界面坏了
  （与现有 `set_providers()` 里"下拉是空的看起来像坏了"的注释同一判断）。
- **选择即生效**：下拉的浏览动作不改值，所以不存在误触发；去掉保存按钮同时消掉
  "待保存 vs 已生效"这个最容易骗到人的状态。
- **不删 `ModelList` 控件**：厂商管理页还在用。
- 不新增"按能力过滤厂商模型名"之外的过滤逻辑；不做远程体积/价格等元数据。

人工验收：
1. 打开「模型设置」→ 每张卡只有**一个**下拉加一行状态；
2. 展开下拉 → 本地组在最上、当前生效项带 `●`；云端按厂商分子组，
   当前生效厂商排最前；无 Key 的厂商合并成一条 note 且写着"未配置 Key"；
3. 本机没配任何 Key 时云端组**只有那一条提示**（不做假列表）；
4. 在下拉里直接输入 `ep-20260101` 这类清单外的名字 → 能选中并生效；
5. 选一个云端模型 → 关窗重开仍是它；跑一次分析，日志里的后端与模型名随之变化；
6. 配好一家厂商的 Key → 重开窗口，该厂商子组自动出现且列出了它的模型；
7. 选了一个未测通的厂商模型 → 状态行指名说差哪一项，且实际仍走本地。
