# 分集设置：目标值自动反算 + 滚轮防误改

## Summary

两件事，都在设置表单与输入控件层面：

1. **目标值实时反算**：选「按目标时长」时，目标集数**只读并实时反算**（N = round(T/D) 并夹到可行区间）；选「按目标集数」时反之（时长 = T/N 只读显示）。想直接指定集数就切模式。
2. **滚轮不改值**：全应用的数值框与下拉框（设置 7 个数值框 + 策略下拉、导出 CRF/编码速度/码率、导入音轨、模型量化档位）滚轮一律不改变值，页面照常滚动。

已拍板：反算字段**只读**、滚轮范围**全应用（数值框 + 下拉框）**。

## Proposed Changes

### 1. `app/gui/widgets/no_wheel.py`（新建）

三个子类 + 一个共用滚动转发 mixin：

```python
class _WheelToScrollArea:
    """滚轮不改值：把滚动量交给最近的滚动区，没有滚动区就只吞掉。"""
    def wheelEvent(self, event) -> None:
        area = self._enclosing_scroll_area()
        if area is None:
            event.ignore()
            return
        bar = area.verticalScrollBar()
        bar.setValue(bar.value() - event.angleDelta().y())
        event.accept()

class NoWheelSpinBox(_WheelToScrollArea, QSpinBox): ...
class NoWheelDoubleSpinBox(_WheelToScrollArea, QDoubleSpinBox): ...
class NoWheelComboBox(_WheelToScrollArea, QComboBox): ...
```

- 用 `parentWidget()` 上溯找 `QAbstractScrollArea`（找不到就不改值也不滚）。
- 显式转发而不是只 `ignore()`：Qt 的传播行为在不同版本/嵌套下不一致，显式设置滚动条值结果可预测，且**无论如何都不会改值**。
- `widgets/__init__.py` 导出这三个类。

- 派生字段只读时同时 `setButtonSymbols(NoButtons)`（去掉步进箭头，彻底避免误触），并 `setEnabled(True)` 让它保持可读（不再灰掉）。

**d. 反算规则**（在 `check_feasibility` 成功之后计算，复用同一份 report）：

- 模式A/推荐（D 是输入）：
  - `total = state.total_seconds`；None → help 文案「导入源片后自动计算」，数值不动。
  - `N = round_half_up(total / D)`，再夹到 `[report.min_episodes, report.max_episodes]`；
  - 若 `report.min_episodes > report.max_episodes`（无解）→ **不改数值**，help 写「当前参数无解，无法反算集数」，面板照旧给出无解理由与可操作提示。
- 模式B（N 是输入）：`D = float(Fraction(total, N))`，`duration_spin.setValue(D)`（控件按 3 位小数显示）；help 写「由总时长 ÷ 目标集数自动计算（内部全精度，界面显示才取整）」——与可行性面板里已有的措辞一致。

**e. `collect_settings()` 不动**：派生字段的值仍会被收集进 settings，但内核在该模式下忽略它（见 Current State Analysis），行为不变。

## Assumptions & Decisions

- 反算只在有源片（`state.total_seconds` 非 None）时进行；无源片时保留现值并提示。
- 取整用 `round_half_up`（与 plan.py 同源），再夹到 `[⌈T/U⌉, ⌊T/L⌋]`；无解不猜值。
- 模式B 的时长显示取 3 位小数（控件现有精度），模型内部仍是精确的 `Fraction(T, N)`——不引入精度漂移。
- 推荐模式沿用模式A 的规则（内核同样以目标时长为输入）。
- 滚轮方案选择"显式转发给滚动区"而不是只 `ignore()`，因为后者依赖 Qt 的传播实现，结果不可预测；显式转发无论嵌套多深都成立。
- 只读字段仍参与 `collect_settings`（写进 settings 但被内核忽略），不额外加"跳过收集"的分支，避免两套真相。
